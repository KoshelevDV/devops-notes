# AGENTS.md — devops-notes

## What is this

Личная DevOps-вики Daniil. Заметки на русском языке — инструкции, гайды, решения
задач из реальной практики. Ведёт AI-ассистент Afflictus (преемник Hermes) по триггеру.

**Триггер:** `"Нужна заметка: <вопрос>"` → создать/обновить заметку, закоммитить, сообщить.

## Stack

Markdown + Git. Никакого генератора сайтов, никаких зависимостей.

## Structure

Три слоя (Karpathy LLM Wiki pattern):

```
raw/           — неизменяемые исходники (статьи, веб-страницы). Только чтение.
wiki/          — скомпилированные знания (markdown-заметки). LLM пишет.
  index.md     — полный каталог всех заметок с ссылками и датами
  log.md       — append-only хронология: ingest, query, lint
kubernetes/    — k8s, etcd, ingress, helm, операторы
docker/        — образы, compose, registry, troubleshooting
linux/         — команды, systemd, сеть, производительность
security/      — CVE, hardening, секреты, аудит, AppSec
networking/    — сети, DNS, firewall, VPN, балансировщики
nginx/         — конфиги, security hardening, proxy
databases/     — PostgreSQL, бэкапы, миграции, HA
ci-cd/         — пайплайны, GitLab CI, деплой
helm/          — чарты, values, репозитории
git/           — workflow, хуки, troubleshooting
ai/            — AI-агенты, RAG, автоматизация
apps/          — инструменты и приложения
api/           — API-справочники
monitoring/    — Prometheus, Grafana, Pushgateway, алерты
_template.md   — шаблон новой заметки
README.md      — оглавление
AGENTS.md      — этот файл
SKILL.md       — схема для AI-ассистента
```

## Development Rules

### Обязательный формат каждой заметки

```markdown
# <Заголовок>

## 🎯 Проблема
Что за ситуация или вопрос. Конкретно и кратко.

## ✅ Решение
Шаги, команды, примеры. Копипаст-ready.

## 📎 Официальная документация
- [Название](URL)

## 🔗 Источники
- Reddit, форумы, статьи

## ⚠️ Подводные камни
Что не очевидно. Где можно ошибиться.
```

### Правила написания
- Язык: **только русский** (код/команды — английский, это нормально)
- Команды — в code blocks, copy-paste готовые
- Конкретика > теория: реальные примеры, реальные команды
- Подводные камни обязательны — это самая ценная часть
- Официальные доки ссылкой, не пересказывать
- Reddit/форумы — если есть, добавить; люди там часто находят решения которых нет в доках

### Git
- Коммит сразу после создания/обновления заметки
- Сообщение: `<раздел>: <краткое описание>`
  - Пример: `security: AppSec Platform stack (Trivy + D-Track + DefectDojo + Semgrep)`
  - Пример: `networking: B2E store vs remote access control`
- Push: `git push https://KoshelevDV:$(gh auth token)@github.com/KoshelevDV/devops-notes.git main`

### Когда создавать новую заметку vs обновлять существующую
- Новая тема → новый файл в нужном разделе
- Дополнение к существующей теме → обновить существующий файл
- Новый раздел → создать директорию, добавить в README.md оглавление
- После каждой заметки → обновить wiki/index.md и добавить запись в wiki/log.md

### Каскадные обновления (Karpathy cascade)
Когда новая заметка затрагивает существующие:
1. Проверь grep -rli по ключевым терминам из новой заметки
2. Обнови все затронутые заметки — добавь кросс-ссылки, скорректируй устаревшие данные
3. В лог добавь `- Updated: <заметка>` для каждой обновлённой

### Линтинг (health-check)
Периодически (каждые ~5 заметок или по команде "прочекай вики"):
- Сверка wiki/index.md с реальными файлами (нет потерянных, нет битых ссылок)
- Поиск внутренних битых ссылок
- Поиск противоречий между заметками
- Поиск orphan-страниц без входящих ссылок
- Поиск пропущенных кросс-ссылок между связанными темами
- Автофикс: битые ссылки → исправить; пропущенные в index → добавить
- Отчёт: противоречия и orphan'ы → сообщить Даниилу
- Запись в log.md: `## [YYYY-MM-DD] lint | N issues found, M auto-fixed`

## CLAUDE.md — Behavioral Guidelines

**Tradeoff:** Эти правила смещены в сторону осторожности. Для тривиальных задач — по ситуации.

### 1. Думай перед кодом

**Не предполагай. Не прячь путаницу. Показывай компромиссы.**

- Озвучивай допущения явно. Если неуверен — спрашивай.
- Если несколько трактовок — покажи их, не выбирай молча.
- Если есть проще решение — скажи.
- Если что-то неясно — остановись, назови что именно, спроси.

### 2. Простота вперёд

**Минимум кода для решения задачи. Никакой спекулятивщины.**

- Без фич сверх запроса.
- Без абстракций для одноразового кода.
- Без «гибкости» и «конфигурируемости» которую не просили.
- Без обработки ошибок для невозможных сценариев.
- Если 200 строк можно сократить до 50 — перепиши.

Спроси себя: «Назвал бы сеньор это переусложнённым?» Если да — упрощай.

### 3. Хирургические правки

**Трогай только то что нужно. Прибирай только за собой.**

- Не «улучшай» соседний код, комментарии, форматирование.
- Не рефакторь то что не сломано.
- Следуй существующему стилю, даже если сделал бы иначе.
- Заметил мёртвый код? Упомяни — не удаляй.

Когда твои изменения создают orphans:
- Убери импорты/переменные/функции которые ТВОИ правки сделали неиспользуемыми.
- Не удаляй ранее существовавший мёртвый код без явного указания.

Тест: каждая изменённая строка должна прослеживаться до запроса пользователя.

### 4. Целенаправленное исполнение

**Определи критерии успеха. Итерации до проверки.**

Трансформируй задачи в проверяемые цели:
- «Добавь валидацию» → «Напиши тесты на невалидный ввод, потом сделай чтобы проходили»
- «Почини баг» → «Напиши тест который воспроизводит, потом почини»
- «Отрефакторь X» → «Убедись что тесты проходят до и после»

Для многошаговых задач — краткий план:
1. [Шаг] → проверить: [чек]
2. [Шаг] → проверить: [чек]

Сильные критерии успеха позволяют работать автономно. Слабые («сделай чтобы работало») требуют постоянных уточнений.

---

**Эти правила работают если:** меньше лишних изменений в диффах, меньше переписываний из-за переусложнения, уточняющие вопросы появляются до реализации а не после ошибок.

## Pitfalls

- Не создавать заметки без раздела "Подводные камни" — это самая ценная часть
- Не забывать обновлять `README.md` при добавлении нового раздела (папки)
- Триггер — именно `"Нужна заметка: <вопрос>"`, не `"запиши"` или `"сохрани"`
